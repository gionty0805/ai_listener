# 배포·운영 가이드

## 1. 사전 준비
| 항목 | 내용 |
|---|---|
| 서버 | Linux 1대 (2 vCPU / 4GB 이상), Docker·Docker Compose |
| 도메인 | 예: `listener.example.com` — **HTTPS 필수** (모바일 브라우저 마이크 정책) |
| Claude API 키 | Anthropic Console에서 발급 → `ANTHROPIC_API_KEY` |
| SMTP | 사내 메일 릴레이 또는 발송 전용 계정 |
| 웹훅(선택) | Slack Incoming Webhook URL / Teams Workflows 웹후크 URL |
| 사내 Whisper(선택) | OpenAI 호환 `/v1/audio/transcriptions` 제공 서버 (예: faster-whisper-server) |

## 2. 배포 (Docker Compose + Caddy 자동 HTTPS)
```bash
git clone <repo> ai_listener && cd ai_listener
cp .env.example .env          # 값 입력 (아래 3장)
vi Caddyfile                  # 도메인 변경 (사내망 전용이면 tls internal)
docker compose up -d --build
docker compose logs -f app    # "요약 엔진: claude (claude-opus-5-5)" 확인
```
사내망에서 공인 인증서를 받을 수 없으면 사내 CA 인증서를 Caddy에 지정하거나 `tls internal` 후 단말에 루트 인증서를 배포한다.

### Docker 없이 실행
```bash
npm install --omit=dev
npm start                     # 기본 3000 포트, 앞단에 HTTPS 리버스 프록시(Nginx 등) 필요
```
Nginx 사용 시 `client_max_body_size 60m;` 설정.

## 3. 주요 환경변수
| 변수 | 기본값 | 설명 |
|---|---|---|
| `ANTHROPIC_API_KEY` | — | 설정 시 Claude 요약, 없으면 mock(데모) 모드 |
| `CLAUDE_MODEL` | `claude-opus-5-5` | 요약 모델 |
| `CLAUDE_EFFORT_FINAL` / `CLAUDE_EFFORT_CHUNK` | `high` / `medium` | 사고 깊이·비용 조절 |
| `CLAUDE_FALLBACKS` | `true` | 거절 시 서버측 자동 폴백 |
| `CHUNK_MINUTES` / `CHUNK_MAX_CHARS` | `10` / `12000` | 중간요약 구간 |
| `SINGLE_PASS_MAX_CHARS` | `200000` | 이 이하면 원문 단일 패스 최종 요약 |
| `LIVE_NOTES` | `true` | 녹음 중 중간요약 |
| `STT_MODE` | `browser` | `browser` 또는 `whisper` |
| `WHISPER_API_URL` / `WHISPER_API_KEY` / `WHISPER_MODEL` | — | 서버 STT |
| `AUDIO_SEGMENT_SECONDS` | `300` | 서버 STT 업로드 단위 |
| `KEEP_AUDIO` | `false` | 요약 후 원본 음성 보관 여부 |
| `APP_ACCESS_TOKEN` | — | 접근 코드 (**운영에서 필수**, 없으면 기동 거부) |
| `ALLOW_NO_AUTH` | 운영 `false` | 접근 코드 없이 기동 허용 (권장하지 않음) |
| `TRUST_PROXY` | `false` | 프록시 뒤에서 `X-Forwarded-For`로 클라이언트 IP 판별 (compose는 `true`) |
| `RATE_LIMIT_PER_MINUTE` / `RATE_LIMIT_COSTLY_PER_MINUTE` | `240` / `6` | IP당 분당 한도 (전체 / 생성·요약·발송) |
| `MAX_TRANSCRIPT_LINES` / `MAX_AUDIO_SEGMENTS` | `20000` / `150` | 세션당 상한 |
| `MAIL_ALLOWED_DOMAINS` | — | 메일 수신 허용 도메인 (예: `example.com`) |
| `PUBLIC_BASE_URL` | — | 메일·메신저의 "웹에서 보기" 링크 |
| `SMTP_*`, `MAIL_FROM`, `AUTO_SEND_EMAIL` | — | 메일 |
| `WEBHOOK_URL`, `WEBHOOK_FORMAT`, `AUTO_SEND_WEBHOOK` | — | 메신저 (`slack`/`teams`/`generic`) |

## 4. 배포 전 점검표
- [ ] HTTPS 접속, 모바일(안드로이드 Chrome·iOS Safari)에서 마이크 권한 팝업 확인
- [ ] 5분 테스트 녹음 → 요약 → 메일 수신 → .ics 캘린더 등록 확인
- [ ] 60분 이상 녹음 시 화면 꺼짐 없는지(Wake Lock), 중간요약 생성 확인
- [ ] `APP_ACCESS_TOKEN` 설정(충분히 긴 임의 문자열), `.env` 권한 600
- [ ] `MAIL_ALLOWED_DOMAINS`에 사내 도메인 지정
- [ ] `package-lock.json` 생성·커밋 후 `npm audit` 확인
- [ ] 개인정보 처리 동의 문구·보관 기간 정책 법무 승인
- [ ] 데이터 폴더 백업 설정

## 5. 운영
| 항목 | 방법 |
|---|---|
| 로그 | `docker compose logs app` — 요약 실패는 `[pipeline:<id>]`로 기록 |
| 헬스체크 | `GET /api/config` (Dockerfile HEALTHCHECK) |
| 백업 | `./data` 폴더 일 1회 스냅샷 |
| 보관 기간 | 예: 90일 지난 세션 삭제 — `find data/sessions -maxdepth 1 -mtime +90 -exec rm -rf {} +` 을 cron으로 (정책 확정 후) |
| 비용 모니터링 | 세션별 `summaryMeta.usage`·`chunks[].usage`에 토큰 사용량 저장 → 월별 집계, Anthropic Console 사용량과 대조 |
| 모델 교체 | 평가셋으로 비교 후 `CLAUDE_MODEL`만 변경하고 재시작 |
| 장애 | 요약 실패 세션은 화면에서 "다시 요약", 서버 재시작 시 요약 중 세션 자동 재처리 |
